# S3 — consumer-side daemon

The documented default is a **consumer-side daemon** that pulls objects to local disk. Traversal (`query`, `walk_chronological`, `get_node`) then runs against a real filesystem at `$OKF_REPLICA_ROOT`.

Direct bucket walking remains supported but is not the documented path. Indexes are never a dependency.

## Shape

```
┌─────────────┐  pull objects   ┌──────────────────┐  stdio MCP   ┌──────────┐
│  S3 bucket  │ ──────────────► │ $OKF_REPLICA_ROOT │ ◄──────────► │  agent   │
│  (source)   │   daemon, not   │  local disk       │  query/walk  │          │
└─────────────┘   the MCP       └──────────────────┘              └──────────┘
```

The daemon is an operator concern. This plugin does not invent a bucket name, an AWS account, or a host. Point it at paths the human already owns, the same way `remote_rsync.py` takes `$SECOND_BRAIN_ROOT` → `$OKF_REPLICA_ROOT`.

## Why not walk S3 from MCP

- `query` is cursor-paginated against a live tree. S3 list cursors and filesystem paths are different kinds of cursor; mixing them under concurrent writes is how offsets drift.
- Index-free correctness means a directory scan is a correct answer. An S3 LIST is not a directory.
- Read-only remote stays stdio against a replica the operator already pulled.

## Replica telemetry

Whether the daemon copies `*.telemetry.md` is the same open question as rsync `--exclude-telemetry`. Default of the pull helper is to include it; pass `--exclude-telemetry` to drop it.
