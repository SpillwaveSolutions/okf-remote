# S3

## Writer path — push

A local watcher observes `$SECOND_BRAIN_ROOT` and **puts** objects into the bucket. Destination is `$OKF_REPLICA_DEST` (`s3://bucket/prefix`). This plugin never invents a bucket, an AWS account, or a host.

```
┌──────────────────┐  watcher, debounce ~2s  ┌─────────────┐
│ $SECOND_BRAIN_ROOT│ ──────────────────────► │  S3 bucket  │
│  (writer)         │  rsync-push analog      │             │
└──────────────────┘                         └─────────────┘
```

```bash
OKF_REPLICA_DEST=s3://your-bucket/okf \
  python3 scripts/remote_watch.py --src "$SECOND_BRAIN_ROOT"
```

The watcher coalesces: a debounce window (default 2s) plus batching, so a worker finalizing a node does not fire one put per file write. `--exclude-telemetry` drops raw telemetry from the transfer.

## Consumer path — pull daemon (unchanged)

The documented consumer path is a **consumer-side daemon** that pulls objects to local disk. Traversal (`query`, `walk_chronological`, `get_node`) then runs against a real filesystem at `$OKF_REPLICA_ROOT`. Direct bucket walking remains supported but is not the documented path. Indexes are never a dependency.

```
┌─────────────┐  pull objects   ┌──────────────────┐  stdio MCP   ┌──────────┐
│  S3 bucket  │ ──────────────► │ $OKF_REPLICA_ROOT │ ◄──────────► │  agent   │
│             │   daemon, not   │  local disk       │  query/walk  │          │
└─────────────┘   the MCP       └──────────────────┘              └──────────┘
```

The daemon is an operator concern. Point it at paths the human already owns.

## Why not walk S3 from MCP

- `query` is cursor-paginated against a live tree. S3 list cursors and filesystem paths are different kinds of cursor; mixing them under concurrent writes is how offsets drift.
- Index-free correctness means a directory scan is a correct answer. An S3 LIST is not a directory.
- Read-only remote stays stdio (or network-with-OAuth) against a replica the operator already pulled.

## Replica telemetry

Whether the transfer copies `*.telemetry.md` is the same flag as rsync `--exclude-telemetry`. Default of the helper is to include it; pass `--exclude-telemetry` to drop it.
